# 🔥 FireDashboard

一個只給自己用的「營火」：記錄台股、美股的持股，看自己離 **Coast FIRE** 還有多遠。

它刻意設計成**不讓人焦慮**的樣子。打開首頁看到的不是一堆紅綠數字，而是一堆營火：

- 每一根**柴**是一檔持股，越粗代表占比越大。
- **火勢**是 Coast FIRE 達成率。火燒過那條線，代表從今天起不再投入，靠複利也能在退休時達標。
- 跌的那天只是「有點風」，火晃一下，柴都還在。

另外還有一個**收集冊**模式，只看股數、不看市值，把存股當成收集卡片：每天打卡拿星星、升等、換自己設定的小獎勵。

> 什麼是 Coast FIRE？簡單說就是：存到某個金額後，就算之後一塊錢都不再存，光靠報酬也能在退休那天長到足夠的金額。

## 第一次安裝

只需要一台裝好 **Docker** 和 **Docker Compose** 的電腦（Linux VM 用終端機就可以，不需要 Docker Desktop）。

```bash
git clone https://github.com/BardKidd/FireDashboard.git
cd FireDashboard
docker compose up -d --build
```

等它建置完，用瀏覽器打開 <http://localhost:8080> 就好。

第一次啟動時，後端會去 Yahoo Finance 抓近 2 年的股價、股息和匯率，可能要等一兩分鐘數字才會出來。

### 想換埠號，或從別台電腦連進來

```bash
cp .env.example .env
```

打開 `.env` 修改：

| 設定 | 意思 | 預設 |
| --- | --- | --- |
| `FIRE_PORT` | 網址要用的埠號，8080 被占用時改這裡 | `8080` |
| `FIRE_BIND` | `127.0.0.1` 只有這台電腦能開；`0.0.0.0` 同網路的其他裝置也能開 | `127.0.0.1` |

改完執行 `docker compose up -d` 讓設定生效。

> ⚠️ 這個系統**沒有登入功能**。設成 `0.0.0.0` 代表同網路的任何人都看得到你的資產，請只在信任的家用網路這樣做；要放到外網，請先在前面加一層有帳密的 reverse proxy。

## 日常維護

| 想做的事 | 指令 |
| --- | --- |
| 更新到最新版 | `git pull && docker compose up -d --build` |
| 停止 | `docker compose down` |
| 再次啟動 | `docker compose up -d` |
| 看後端在做什麼 | `docker compose logs -f backend` |

### 資料在哪？怎麼備份？

所有資料都在一個檔案：**`./data/fire.db`**。備份就是複製這個檔案，還原就是把它放回去。更新程式、重建容器都不會動到它。

### 股價會自己更新嗎？

會。每天台灣時間兩次：

- **06:30**（週二到週六）：美股收盤後
- **14:30**（週一到週五）：台股收盤後

電腦關機幾天也沒關係，下次啟動時會自動把缺的日子補齊。想立刻更新，按右上角的「更新報價」。

## 開始使用

第一次打開時會自動跳出**操作導覽**，帶你認識畫面上每個區塊。之後想再看一次，按右上角的「導覽」。數字旁邊的小 **?** 可以看它是怎麼算出來的。

### 1. 填入你的基本參數

右上角「參數設定」：出生年月、想幾歲退休、退休後一年要花多少、安全提領率、預期報酬率、通膨，以及每月會投入多少。Coast 線就是從這些算出來的。

### 2. 加入持股

在持倉表按「新增標的」，輸入代號就好：

- **台股**：只打數字，例如 `0050`、`00687B`，系統會自己判斷是上市還上櫃。
- **美股**：直接打代號，例如 `VOO`、`SSO`。

### 3. 每次買賣都記一筆

按該列的「記錄」。日期可以選過去的日子補登，歷史曲線會自動重算。

### 4. 股息不用自己記

系統會依除息日當時的持股自動把股息記到現金：

- 美股先扣 30% 預扣稅。
- 台股單筆 ≥ 2 萬元再扣 2.11% 二代健保。

（這兩個比例都可以在設定裡改。）

### 5. 約定存款（選用）

像「每月存 1 萬、10 年後領 200 萬」這種固定約定，可以在持倉表按「＋ 約定存款」加入。系統會算出它隱含的年報酬，一起算進總資產。到期領回後勾選「已領回」，再把那筆錢記到台幣現金。

### 一次匯入很多持股

如果持股很多，可以寫成一個 JSON 檔一次匯入。格式範例在 [`backend/app/seed.py`](backend/app/seed.py) 最上面。把檔案放到 `./data/initial_holdings.json`，然後執行：

```bash
docker compose exec backend python -m app.seed /data/initial_holdings.json
```

已經存在的標的會略過，不小心跑兩次也不會重複。

### 背景音樂

右上角的喇叭按鈕可以開關營火旁的背景音樂，預設是關的。

## 收集冊模式

右上角切到「收集冊」。這裡**只看股數**，不顯示市值和損益，適合想安心存股、不想天天看漲跌的時候。

- **每日打卡**：每天一次，拿 10 顆星星，還可以留一句話給未來的自己。連續紀錄是以「週」計算，一週內打過一次就不會斷。
- **收集卡**：每檔持股一張卡，股數到達里程碑就升一階、解鎖徽章。
  - 台股：100 股 → 500 股 → 1 張 → 2 張 → 3 張 → 5 張 → 10 張…
  - 美股：1 股 → 5 股 → 10 股 → 20 股 → 50 股…
- **目標籃子**：把你的 Coast 目標換算成「每檔還要收集幾股」，也可以自己調整。
- **特價雷達**：價格低於近 60 日平均時提醒你「同樣的錢現在能多收幾 % 的股數」。
- **收集曲線**：股數隨時間的變化。股票分割不會讓曲線突然跳一階。
- **成就、等級與獎勵**：打卡、達到里程碑、領到股息都會拿到星星。星星可以換你自己設定的真實獎勵（例如「吃一頓好的 300 顆」），兌換不會讓等級下降，已拿到的成就也不會被收回。

## 常見問題

**畫面上方出現「部分標的更新失敗」？**
Yahoo Finance 偶爾會限流，通常下一次排程就會好。滑鼠移上去可以看是哪幾檔。

**某檔股票分割後數字怪怪的？**
大部分分割系統會自動處理。少數台股分割 Yahoo 沒有提供（0050 在 2025-06-18 的 1 拆 4 已內建），遇到其他的，到該標的的「編輯」補上分割日期與比例即可。

**打不開網頁？**
先確認容器有在跑：`docker compose ps`。如果是從別台電腦連，記得 `.env` 的 `FIRE_BIND` 要設成 `0.0.0.0`。

**這些數字可以當投資建議嗎？**
不行。這只是個人規劃用的參考工具。

## 給開發者

### 技術架構

| 部分 | 使用的技術 |
| --- | --- |
| 前端 | Vue 3、TypeScript、Tailwind CSS、ECharts，用 Vite 8 建置，正式環境由 nginx 提供 |
| 後端 | FastAPI、SQLAlchemy、APScheduler、yfinance |
| 資料庫 | SQLite（`./data/fire.db`） |
| 部署 | Docker Compose，兩個容器（frontend、backend） |

設計決定的摘要在 [SPEC.md](SPEC.md)，完整規格書連結也在裡面。

### 本機開發

```bash
# 後端
cd backend
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
pytest                          # 跑測試
uvicorn app.main:app --reload   # http://localhost:8000

# 前端（另開一個終端機）
cd frontend
npm install
npm run dev                     # http://localhost:5173，/api 會轉到 localhost:8000
```

後端環境變數：

- `FIRE_DB_PATH`：資料庫位置，預設 `./data/fire.db`。
- `FIRE_DISABLE_SCHEDULER=1`：關掉自動更新與啟動時的補資料，開發時比較安靜。

### 程式放在哪

- 導覽與 **?** 說明的文字都集中在 [`frontend/src/guide/content.ts`](frontend/src/guide/content.ts)。
- 收集冊的畫面在 `frontend/src/components/collect/`，規則在 `backend/app/game.py`。
- 抓價、分割與排程在 `backend/app/fetcher.py`；Coast FIRE 計算在 `backend/app/calculator.py`。

### 關於 Yahoo 的股價

Yahoo 提供的收盤價已經做過分割調整。系統會保存 Yahoo 的原始值，算淨值時再依分割紀錄換回當天的實際價格，所以「當時股數 × 當時價格」在分割前後都是對的。
